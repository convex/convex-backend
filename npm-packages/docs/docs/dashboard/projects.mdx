A project corresponds to a codebase that uses Convex, which contains a
production deployment and one personal deployment for each team member.

## The projects list

The [landing page](https://dashboard.convex.dev) lists your team's projects.
Search by project name or slug, filter by [tag](#project-tags), and switch
between grid and list views with the buttons next to the search box.

Each project shows its name, slug, tags, and when it was created, along with
quick links to its deployments:

- **Production**: the project's default
  [production deployment](/dashboard/deployments/deployments.mdx).
- **Development**: your default personal development deployment in the project.
- **Recently viewed**: the non-default deployment you most recently opened in
  the project.

The icon after the quick links opens the list of deployments you've created in
the project.

<Screenshot
  story="docs/components/ProjectCard#With Recent Deployment"

/>

## Creating a project

Projects can be created from the dashboard or from the CLI with
[`npx convex dev`](/cli/reference/dev.mdx). To create a project from the
dashboard click on the Create Project button.

## Switching projects

Once you're inside a project, click the project name at the top of the dashboard
to switch to another project in the team. Typing filters the team's projects,
and the caret at the end of each row opens that project's pages and
[deployments](/dashboard/deployments/deployments.mdx), so you can jump straight
into one of them.

## Project tags

Tags are short labels, that you can attach to projects to organize them. Use
them to [filter the projects list](#filtering-projects-by-tag) and to
[grant custom-role access to groups of projects](/team-management/custom-roles.mdx#selectors-by-kind).

### Adding tags

Tags can be added when a project is first created on the dashboard.

<Screenshot
  story="docs/pages/Projects#Create Project With Tags"
  alt="Adding tags to a new project"
/>

To change an existing project's tags, open its
[Project Settings](#project-settings) page and edit the Tags field in the Edit
Project form.

<Screenshot
  story="docs/pages/project/ProjectSettings#Tags"
  alt="Editing tags in project settings"
/>

A project can have up to 5 tags. Each tag can be up to 32 characters long, and
can contain only letters, numbers, `-`, and `_`.

### Filtering projects by tag

To show only the projects with a given tag, pick it from the tag filter next to
the search box on the projects list.

<Screenshot
  story="docs/pages/Projects#Filtered By Tag"
  alt="Projects list filtered by tag"
/>

## Project Settings

You can access project-level settings by clicking on the triple-dot `⋮` button
on each Project card on the Projects page.

<Screenshot story="docs/components/ProjectCard" alt="Project card menu" />

On the [Project Settings page](https://dashboard.convex.dev/project/settings),
you can:

- Update your project's name, slug, and [tags](#project-tags).
- Manage the project's Admins. See
  [Roles and Permissions](/dashboard/teams/teams.mdx#roles-and-permissions) for
  more details.
- View the amount of [usage metrics](/dashboard/teams/teams.mdx#usage) your
  project has consumed.
- Manage [custom domains](/production/custom-domains.mdx) for your production
  deployment (in Deployment Settings).
- Generate deploy keys for your production deployment (in Deployment Settings)
  and preview deployments.
- Create and edit
  [default environment variables](/production/environment-variables.mdx#project-environment-variable-defaults).
- View instructions to regain access to your project, should you lose track of
  your `CONVEX_DEPLOYMENT` config.
- Permanently delete the project.

<Screenshot story="docs/pages/project/ProjectSettings" alt="Project settings" />

## Transferring a project to another team

You can move a project to another team you’re a member of from the
[Project Settings page](https://dashboard.convex.dev/project/settings#transfer-project).
The project keeps its slug, deployments, data, environment variables, and deploy
keys — only its owning team changes.

After the transfer, the project URL changes from
`https://dashboard.convex.dev/t/<old-team>/<project>` to
`https://dashboard.convex.dev/t/<new-team>/<project>`. Members of the source
team lose access to the project, unless they have permissions on the new team
allowing them to see the project.

<Screenshot story="docs/components/TransferProject" alt="Transfer project" />

To transfer a project:

- You need to be an admin on the **source team** (or have the `project:transfer`
  permission if using [custom roles](/team-management/custom-roles.mdx))
- You also need to be an admin on the **destination team** (or have the
  `project:receive` permission if using
  [custom roles](/team-management/custom-roles.mdx)).

## Deleting a project

To delete a project, click on the triple-dot `⋮` button on the Project card and
select "Delete". You may also delete your project from the Project Settings
page.

Once a project is deleted, it cannot be recovered. All deployments and data
associated with the project will be permanently removed. When deleting a project
from the dashboard, you will be asked to confirm the deletion. Projects with
activity in the production deployment will have additional confirmation steps to
prevent accidental deletion.
