The email + password sign-in method implements password-based login where each
account is identified by a validated email address. It handles:

- Sign-up with email validation: the account is created immediately, but the
  user can sign in only after they open the validation link.
- Sign-in.
- Change password and change email, which require the current password and send
  a security notification to the affected address.
- Password reset through a reset link received by email.

A validation link works only in the browser (or app) that started the flow: the
client keeps a secret in its storage, and completion requires both that secret
and the code from the link.

Emails are sent through the
[`@convex-dev/resend`](https://www.convex.dev/components/resend) component.

## Setting up email + password login in your app

<StepByStep>

<Step title="Follow the “Getting started” guide">

First, install Convex Auth and set up the core as described in the
[Getting started](../getting-started.mdx) guide.

</Step>

<Step title="Set up Resend">

This method uses [Resend](https://resend.com) to send emails for account
validation, password recovery, and security notifications.

You will need a domain to send these emails from.

Before going further:

1. [Create a Resend account](https://resend.com/signup)
2. [Set up your domain in Resend](https://resend.com/docs/add-a-domain)
3. [Create a Resend API key](https://resend.com/docs/create-an-api-key)

Then connect Resend to your Convex deployment:

```bash
npm install @convex-dev/resend
npx convex env set RESEND_API_KEY # Press Enter then enter your Resend API key
npx convex env set SENDER_EMAIL no-reply@my-domain.example # Replace this with an email address in your verified domain
npx convex env set SENDER_NAME "My App" # Optional: replace this with the sender name of your emails
```

</Step>

```ts title="convex/convex.config.ts"
// highlight-next-line
```

<Step title="Set up user creation">

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. This function will be used every time someone creates a new
account.

```ts title="convex/users.ts"
import { internalMutation } from "./_generated/server";
import { v } from "convex/values";

export const createUser = internalMutation({
  args: {
    method: v.object({
      name: v.literal("emailPassword"),
      profile: v.object({}),
    }),
  },
  returns: v.id("users"),
  handler: async (ctx) => {
    return await ctx.db.insert("users", {});
  },
});
```

<Step title="Set up the public backend functions">

Set up the `emailPassword` method with `setupEmailPassword` and export the
mutations it hands back once you attach the callback that creates your user
rows, in `convex/auth.ts`:

```ts title="convex/auth.ts"
import { components, internal } from "./_generated/api";
import { env } from "./_generated/server";
import { setupConvexAuth } from "@convex-dev/auth/server";
// highlight-next-line
import { setupEmailPassword } from "@convex-dev/auth/methods/email-password/server";

// The frontend origin the emailed links point at. Set SITE_URL on the
// deployment when the frontend does not run on the Vite default.
const SITE_URL = env.SITE_URL ?? "http://localhost:5173";

const auth = setupConvexAuth({ component: components.auth });
export const { signOut, refreshSession, isAuthenticated } = auth;

export const {
  signUpWithEmailPassword,
  completeSignUpWithEmailPassword,
  signInWithEmailPassword,
  changePassword,
  startChangeEmail,
  completeChangeEmail,
  startPasswordRecovery,
  checkPasswordRecovery,
  completePasswordRecovery,
} = setupEmailPassword(auth, {
  component: components.authEmail,
  passwordComponent: components.authPassword,
  emailSender: {
    kind: "resend",
    sendEmail: components.resend.lib.sendEmail,
    apiKey: env.RESEND_API_KEY,
    // SENDER_EMAIL must be on a domain you verified with Resend, or Resend's
    // onboarding sender (onboarding@resend.dev), which only delivers to the
    // email address of your own Resend account.
    from: `${env.SENDER_NAME ?? "My App"} <${env.SENDER_EMAIL}>`,
  },
  urls: {
    signUp: `${SITE_URL}/validate-email`,
    changeEmail: `${SITE_URL}/confirm-email-change`,
    recovery: `${SITE_URL}/reset-password`,
  },
  // highlight-next-line
}).attachUserCallbacks({
  createUser: internal.users.createUser,
});
```

<Step title="Set up the sign-up page">

In your front-end, set up a route for each flow, starting with creating an
account. Copy the following components into your app. Feel free to customize
them, for instance to use your app’s design system.

```tsx title="src/routes/signUp.tsx"
import { useSignUpWithEmailPassword } from "@convex-dev/auth/methods/email-password/react";
import { useState } from "react";
import { api } from "../../convex/_generated/api";

export function SignUp() {
  const { signUp, pending } = useSignUpWithEmailPassword(api.auth);
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [error, setError] = useState<string | null>(null);
  const [sentTo, setSentTo] = useState<string | null>(null);

  if (sentTo !== null) {
    return (
      <>
        <h1>Validate your email</h1>
        <p>
          We sent a link to <strong>{sentTo}</strong>. Open it to validate your
          address and sign in.
        </p>
        <p>
          Open the link in <strong>this browser</strong>: the link only works in
          the browser you signed up from.
        </p>
      </>
    );
  }

  return (
    <>
      <form
        onSubmit={async (e) => {
          e.preventDefault();
          setError(null);
          const result = await signUp({ email, password });
          if (result.success) {
            setSentTo(email);
            return;
          }
          setError(() => {
            switch (result.userError.error) {
              case "INVALID_EMAIL":
                return "That email address doesn't look valid.";
              case "EMAIL_TAKEN":
                return "An account already exists with that email address.";
              case "RATE_LIMITED":
                return `Too many attempts. Try again in ${Math.ceil(result.userError.retryAfterMs / 1000)} seconds.`;
              case "PASSWORD_TOO_SHORT":
                return `Password must be at least ${result.userError.minimumLength} characters.`;
              case "PASSWORD_TOO_LONG":
                return `Password must be at most ${result.userError.maximumLength} characters.`;
              case "PASSWORD_HAS_SURROUNDING_WHITESPACE":
                return "Password can't start or end with whitespace.";
              case "PASSWORD_TOO_COMMON":
                return "This password is one of the most commonly used passwords. Please choose a different one.";
              case "OTHER_ERROR":
                // The mutation threw unexpectedly; the original error is
                // available on `cause` if you want to log or inspect it.
                console.error("Sign-up failed:", result.userError.cause);
                return "Something went wrong. Please try again.";
              default:
                result.userError satisfies never;
                console.error("Sign-up failed:", result.userError);
                return "Something went wrong. Please try again.";
            }
          });
        }}
      >
        <h1>Sign up</h1>
        <label>
          Email
          <input
            type="email"
            value={email}
            onChange={(e) => setEmail(e.target.value)}
            // "username", not "email" (best practice for password manager support)
            autoComplete="username"
            required
            disabled={pending}
          />
        </label>
        <label>
          Password
          <input
            type="password"
            value={password}
            onChange={(e) => setPassword(e.target.value)}
            autoComplete="new-password"
            required
            disabled={pending}
          />
        </label>
        {error ? (
          <p role="alert">
            <strong>{error}</strong>
          </p>
        ) : null}
        <button type="submit" disabled={pending}>
          {pending ? "Creating account…" : "Create account"}
        </button>
      </form>
      <p>
        Already have an account? <a href="/auth/convex-auth/login">Log in</a>
      </p>
    </>
  );
}
```

<Step title="Set up the email validation page">

Set up the landing page for the link in the sign-up email. It must not require
authentication.

```tsx title="src/routes/validateEmail.tsx"
import { useCompleteSignUpWithEmailPassword } from "@convex-dev/auth/methods/email-password/react";
import type { ReactNode } from "react";
import { useSearchParams } from "react-router-dom";
import { api } from "../../convex/_generated/api";

/**
 * Landing page for the sign-up challenge link (`/validate-email?code=…`).
 * The hook completes the validation as soon as the page opens, which also
 * signs the user in; the page shows the outcome.
 */
export function ValidateEmail() {
  const [params] = useSearchParams();
  const emailCode = params.get("code");
  if (emailCode === null) {
    return <p>This link is incomplete. Use the link from your email.</p>;
  }
  return <ValidateEmailWithCode emailCode={emailCode} />;
}

function ValidateEmailWithCode({ emailCode }: { emailCode: string }) {
  const state = useCompleteSignUpWithEmailPassword(api.auth, { emailCode });

  if (state.status === "loading") {
    return <p>Validating your email…</p>;
  }
  if (state.status === "complete") {
    return (
      <>
        <h1>Email validated</h1>
        <p>
          Your email address is validated and you are signed in.{" "}
          <a href="/auth/convex-auth/">Go to the dashboard</a>.
        </p>
      </>
    );
  }
  switch (state.userError.error) {
    case "MISSING_SECRET":
      return (
        <>
          <h1>Open this link in the browser you signed up from</h1>
          <p>
            For your security, the validation link only works in the browser
            where the sign-up started. Open the link there, or sign up again in
            this browser.
          </p>
        </>
      );
    case "INVALID_CHALLENGE":
      return (
        <ValidateEmailError>
          This link is no longer valid. It may have expired or already been
          used.
        </ValidateEmailError>
      );
    case "INCORRECT_CODE":
      return (
        <ValidateEmailError>
          This is not the latest link. Open the newest email we sent you.
        </ValidateEmailError>
      );
    case "EMAIL_TAKEN":
      return (
        <ValidateEmailError>
          This email address is already in use. Sign in instead.
        </ValidateEmailError>
      );
    case "OTHER_ERROR":
      console.error("Validation failed:", state.userError.cause);
      return (
        <ValidateEmailError>
          Something went wrong. Reload the page to try again.
        </ValidateEmailError>
      );
    default:
      state.userError satisfies never;
      console.error("Validation failed:", state.userError);
      return (
        <ValidateEmailError>
          Something went wrong. Reload the page to try again.
        </ValidateEmailError>
      );
  }
}

function ValidateEmailError({ children }: { children: ReactNode }) {
  return (
    <>
      <h1>Could not validate your email</h1>
      <p role="alert">
        <strong>{children}</strong>
      </p>
      <p>
        <a href="/auth/convex-auth/signup">Sign up again</a> to receive a new
        link.
      </p>
    </>
  );
}
```

<Step title="Set up the change-password form">

Let signed-in users change their password:

```tsx title="src/ChangePasswordForm.tsx"
import { useMutation } from "convex/react";
import { useState } from "react";
import { api } from "../convex/_generated/api";

export function ChangePasswordForm({
  currentEmail,
}: {
  currentEmail: string | undefined;
}) {
  const changePassword = useMutation(api.auth.changePassword);
  const [pending, setPending] = useState(false);
  const [currentPasswordField, setCurrentPasswordField] = useState("");
  const [newPasswordField, setNewPasswordField] = useState("");
  const [signOutOtherSessions, setSignOutOtherSessions] = useState(false);
  const [message, setMessage] = useState<string | null>(null);

  return (
    <form
      onSubmit={async (e) => {
        e.preventDefault();
        setMessage(null);
        setPending(true);
        try {
          const result = await changePassword({
            currentPassword: currentPasswordField,
            newPassword: newPasswordField,
            signOutOtherSessions,
          });
          if (result.success) {
            setCurrentPasswordField("");
            setNewPasswordField("");
            setMessage("Your password was changed.");
            return;
          }
          setMessage(() => {
            switch (result.userError.error) {
              case "NOT_LOGGED_IN":
                return "You are not logged in.";
              case "INVALID_CREDENTIALS":
                return "The current password is incorrect.";
              case "PASSWORD_TOO_SHORT":
                return `Password must be at least ${result.userError.minimumLength} characters.`;
              case "PASSWORD_TOO_LONG":
                return `Password must be at most ${result.userError.maximumLength} characters.`;
              case "PASSWORD_HAS_SURROUNDING_WHITESPACE":
                return "Password can't start or end with whitespace.";
              case "PASSWORD_TOO_COMMON":
                return "This password is one of the most commonly used passwords. Please choose a different one.";
              case "RATE_LIMITED":
                return `Too many attempts. Try again in ${Math.ceil(result.userError.retryAfterMs / 1000)} seconds.`;
              default:
                result.userError satisfies never;
                console.error("Password change failed:", result.userError);
                return "Something went wrong. Please try again.";
            }
          });
        } catch (error) {
          console.error("Change password failed:", error);
          setMessage("Something went wrong. Please try again.");
        } finally {
          setPending(false);
        }
      }}
    >
      <h2>Change password</h2>
      {/* Hidden email, so that password managers know which login to update */}
      <input
        type="email"
        value={currentEmail ?? ""}
        // "username", not "email" (best practice for password manager support)
        autoComplete="username"
        readOnly
        hidden
      />
      <label>
        Current password
        <input
          type="password"
          value={currentPasswordField}
          onChange={(e) => setCurrentPasswordField(e.target.value)}
          autoComplete="current-password"
          required
          disabled={pending}
        />
      </label>
      <label>
        New password
        <input
          type="password"
          value={newPasswordField}
          onChange={(e) => setNewPasswordField(e.target.value)}
          autoComplete="new-password"
          required
          disabled={pending}
        />
      </label>
      <label>
        <input
          type="checkbox"
          checked={signOutOtherSessions}
          onChange={(e) => setSignOutOtherSessions(e.target.checked)}
          disabled={pending}
        />
        Sign out of all other devices
      </label>
      {message ? (
        <p role="alert">
          <strong>{message}</strong>
        </p>
      ) : null}
      <button type="submit" disabled={pending}>
        {pending ? "Changing…" : "Change password"}
      </button>
    </form>
  );
}
```

```tsx title="src/routes/confirmEmailChange.tsx"
import { useCompleteChangeEmail } from "@convex-dev/auth/methods/email-password/react";
import { useSearchParams } from "react-router-dom";
import { api } from "../../convex/_generated/api";

/**
 * Landing page for the change-email confirmation link
 * (`/confirm-email-change?code=…`). The hook completes the change as soon as
 * the page opens; the page shows the outcome. No session is minted: the user
 * already has one.
 */
export function ConfirmEmailChange() {
  const [params] = useSearchParams();
  const emailCode = params.get("code");
  if (emailCode === null) {
    return <p>This link is incomplete. Use the link from your email.</p>;
  }
  return <ConfirmEmailChangeWithCode emailCode={emailCode} />;
}

  const state = useCompleteChangeEmail(api.auth, {
    emailCode,
  });

  if (state.status === "loading") {
    return <p>Confirming your new email…</p>;
  }
  if (state.status === "complete") {
    return (
      <>
        <h1>Email address changed</h1>
        <p>
          The new address is now the primary address of your account.{" "}
          <a href="/auth/convex-auth/">Back to the dashboard</a>.
        </p>
      </>
    );
  }
  switch (state.userError.error) {
    case "MISSING_SECRET":
      return (
        <>
          <h1>Open this link in the browser you started from</h1>
          <p>
            For your security, the confirmation link only works in the browser
            where the email change started.
          </p>
        </>
      );
    case "INVALID_CHALLENGE":
      return (
        <ConfirmEmailChangeError message="This link is no longer valid. It may have expired or already been used." />
      );
    case "INCORRECT_CODE":
      return (
        <ConfirmEmailChangeError message="This is not the latest link. Open the newest email we sent you." />
      );
    case "NOT_LOGGED_IN":
      return (
        <ConfirmEmailChangeError message="Log in first, then open the link again." />
      );
    case "EMAIL_TAKEN":
      return (
        <ConfirmEmailChangeError message="Another account validated this email address first." />
      );
    case "WRONG_USER":
      return (
        <ConfirmEmailChangeError message="This link is for another account. Log in with the account that started the change, then open the link again." />
      );
    case "OTHER_ERROR":
      console.error("Email change failed:", state.userError.cause);
      return (
        <ConfirmEmailChangeError message="Something went wrong. Reload the page to try again." />
      );
    default:
      state.userError satisfies never;
      console.error("Email change failed:", state.userError);
      return (
        <ConfirmEmailChangeError message="Something went wrong. Reload the page to try again." />
      );
  }
}

function ConfirmEmailChangeError({ message }: { message: string }) {
  return (

      </p>
```

## Rate limits

This method rate-limits the flows that send emails or tell whether an address
has an account. When a limit is reached, the call returns a `RATE_LIMITED` error
with `retryAfterMs`, the number of milliseconds until the next attempt can
succeed. Show it to the user, as `logIn.tsx` does above.

Each limit is a token bucket: the user can make as many attempts as the capacity
at once, then the bucket refills at a steady rate.

| Limit                          | Applies to                                                                                                               | Capacity | Refill         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | -------- | -------------- |
| Emails per destination address | Sign-up validation, change-email confirmation, and password reset links sent to one address                              | 5        | 1 every 12 min |
| Emails per client IP           | The same emails, sent from one client IP to any address                                                                  | 20       | 1 every 3 min  |
| Account lookups per client IP  | Sign-in, starting a password reset, and starting a sign-up or an email change (which tells whether the address is taken) | 60       | 1 every minute |
| Password attempts per user     | Sign-in, change password, and change email (which check the current password)                                            | 5        | 1 every minute |

The limit per destination address is shared by all of the kinds of emails. For
instance, a user who requested 5 password reset links in a row must wait about
12 minutes before they can request a link to change their email to that address.
Security notifications, such as the one sent after a password change, don't
count toward these limits.

These values aren't configurable yet.
